    How this stays secure on GitHub Pages

    GitHub Pages is static: everything in the repo is public. So we never put a password or a service_role key in the code. Instead:

    1. Browser uses only the anon (publishable) key — safe to be public.
    2. Supabase checks your email + password on its server and returns a session token.
    3. Row Level Security (RLS) in Supabase allows SELECT only when auth.role() = 'authenticated'.

    If someone copies the HTML, they still can’t read private rows without signing in.

    Where to find your anon key: Supabase Dashboard (your project mais-pac-members) → Project Settings (gear icon) → API → Project API keys → copy anon public key. Paste it into assets/supabase-config.js. Never paste the service_role key anywhere in the repo.

    Vercel option (also free): You can keep the same repo. Import it in vercel.com/new → Framework: Other → deploy. The same members.html works. Benefit: you can later add Vercel Environment Variables (SUPABASE_URL + SUPABASE_ANON_KEY) and server-side checks if you want to protect downloadable files too. For now, no Vercel config is required — static hosting is enough because RLS does the protection.
